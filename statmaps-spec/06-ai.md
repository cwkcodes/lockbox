# 06 — AI Architecture & the Correlation Engine

Design stance: **the AI operates the product, it does not replace it.** The model manipulates layers through the same typed API the UI uses and cites datasets for every claim. It never emits numbers from its own weights — all values come from tool results. This is what keeps AI answers trustworthy, cacheable, and cheap.

## 1. Model strategy

| Workload | Model | Notes |
|---|---|---|
| Interactive query → map (chat) | `claude-sonnet-5` | Tool use, streaming; prompt caching on the (large, static) tool/system prompt |
| Bulk generation at ingest (summaries, facts, quizzes) | `claude-haiku-4-5` | Thousands of items/night; cost-optimised; batch API |
| Map Stories authoring (long-form, Phase 4) | `claude-sonnet-5` | Human-reviewed before publish |
| Embeddings (semantic search) | hosted embedding model (e.g. voyage-3) | Computed at ingest → pgvector |

## 2. Pre-generated artefacts (the cheap 80%)

Generated at ingest/publish time, stored in `ai_summaries`, keyed by dataset version so they regenerate only when data changes:

- **Layer summary** (150 words: what it measures, source, headline patterns, caveats).
- **Facts** ("Vietnam grows 40× more coffee than all of Europe combined") — each fact carries the query that verifies it; a validation step re-runs the query against the data before the fact is stored. Facts that don't verify are discarded.
- **Anomaly notes** (statistical outlier detection runs first — z-scores, year-over-year breaks — and the model *explains* flagged anomalies rather than finding them).
- **Quiz items** (question, 4 options, correct answer, map state that reveals it).
- **Related-dataset suggestions** (embedding neighbours re-ranked by the model with a one-line "why").

Human review queue: artefacts ship as `reviewed=false` (shown with an "AI-generated" badge); editorial spot-checks promote high-traffic ones.

## 3. Interactive query pipeline ("show me countries with high solar but low GDP")

```
user query
   → intent router (small model / classifier): place | layer-search | question
   → if question: claude-sonnet-5 with tools:
        search_layers(q)                  → candidate layers + metadata
        get_layer_values(layer_id, t)     → values keyed by region
        filter_regions(expr)              → e.g. percentile(solar_resource) > 70 AND gdp_pc < 15000
        run_correlation(target, scope)    → correlation engine (§4)
        compose_map(layers[], styles, viewport, time, highlights)
   → output: {map_state, narration, citations[]}  → client renders map_state (same URL-state
     object as 01-product §2.8) and shows narration with dataset citations
```

- **Latency budget:** first token < 1.5 s (streamed narration), map renders as soon as `compose_map` fires (usually before narration completes).
- **Guardrails:** tool results are the only source of values; `filter_regions` runs server-side against ClickHouse (the model writes a constrained expression DSL, not SQL); narration must cite `dataset_id`s present in the tool trace or the response is rejected and retried.
- **Caching:** normalised query → response cache (24 h) since popular questions repeat heavily.
- Example resolutions:
  - *"Show places similar to Japan"* → region-embedding similarity (each region gets a vector of its standardised indicator values across marquee datasets; cosine neighbours → highlight map + "similar because: aging population, high urbanisation, low fertility, high life expectancy").
  - *"Countries that consume more coffee than they produce"* → `filter_regions(consumption > production)` over two layers → highlight map.
  - *"Best place for offshore wind"* → multi-criteria: wind resource (raster zonal stats, precomputed per EEZ) × water depth × grid proximity → ranked hex map with explicit weights the user can adjust.

## 4. The Correlation Engine (the differentiator)

### 4.1 UX contract

User picks a target (layer or question). Output: a ranked list of relationships, each rendered as **(a)** a bivariate scatter (log scales where appropriate) with the regression line, **(b)** a synced side-by-side map pair, and **(c)** a plain-language card: *"Strong positive relationship (ρ = 0.81, n = 164 countries, 2019). Countries with higher X tend to have higher Y. **This does not mean X causes Y** — both track GDP per capita (partial ρ controlling for GDP: 0.24)."*

Honesty is a product feature: every card shows n, the confounder check, and a confidence tier — never a bare correlation.

### 4.2 Statistical methodology (normative)

1. **Scope:** country-level (later ADM1), one target variable, a chosen year (or pooled years with region fixed effects — Phase 4).
2. **Candidate set:** all numeric datasets with ≥ 40 overlapping regions with the target at that time.
3. **Per pair compute:** Spearman ρ (primary — robust to the heavy skew typical of country data) + Pearson r on log-transformed strictly-positive variables; n; p-value.
4. **Multiple-comparison control:** Benjamini–Hochberg FDR across the full scan (scanning 3,000 datasets *guarantees* spurious hits at raw p < 0.05 — this correction is non-negotiable).
5. **Confounder screen:** partial correlation controlling for log GDP per capita and population (the two universal confounders in country data). Report both raw and partial; if partial collapses (|ρ_partial| < 0.15), the card leads with "largely explained by GDP".
6. **Galton/spatial-autocorrelation caveat:** neighbouring countries aren't independent samples. Compute Moran's I on residuals; flag high-spatial-autocorrelation pairs with reduced effective n. (Phase 4: proper spatial regression; Phase 2–3: honest flagging.)
7. **Ranking score:** `|ρ_partial| × log(n) × novelty` where novelty down-weights the trivially-correlated cluster (all development indicators inter-correlate ~0.8; showing "life expectancy correlates with school enrolment" forever is noise). Novelty = 1 − max correlation between candidate and already-shown results.
8. **Tiers shown to user:** `strong / moderate / weak` + `robust / partly-explained-by-development / likely-spurious`.

### 4.3 Implementation

- Runs in the **Python stats service against ClickHouse** (04-database §9). One full scan for one target: pull the target vector + stream candidate vectors, compute in vectorised NumPy — target < 3 s cold.
- **Nightly precompute:** full pairwise matrix across the top ~500 marquee datasets (ρ, n, p_adj) stored in ClickHouse; interactive requests over marquee targets are instant lookups; long-tail targets compute on demand and cache in `correlation_results`.
- The AI layer sits *on top*: `run_correlation` is a tool; the model narrates and picks illustrative examples but **never computes statistics itself**.
- Engine versioned (`engine_version`) so methodology improvements invalidate caches cleanly.

### 4.4 Failure modes designed against

| Risk | Mitigation |
|---|---|
| Spurious-correlation embarrassment ("margarine ∝ divorce") | FDR + confounder screen + novelty ranking + explicit "likely-spurious" tier; a "why this might be meaningless" expander on every card |
| Users read causation | Language templates never use causal verbs; causation disclaimer on every card; educational one-pager linked everywhere |
| Ecological fallacy (country-level → individual-level claims) | Card states the unit of analysis; blog/education content |
| Cherry-picked years | Default to latest common year; sparkline of ρ over time shows stability |

## 5. Cost control

AI spend is the most elastic cost line (03-architecture §8). Levers, in order: pre-generation over interactive; response caching (popular queries are extremely head-heavy); prompt caching (tool schemas + system prompt are static); haiku-class models for bulk; per-tier daily AI quotas (05-api §3). Budget alarm at $/day thresholds with automatic degradation to cached-only mode rather than outage.

## 6. Safety & quality

- All AI text carries an "AI-generated" badge until editorially reviewed.
- Data about contested topics (borders, ethnicity, religion, conflicts) uses reviewed templates; the model is instructed to present source framing, not adjudicate disputes.
- Prompt-injection surface: user content (map titles, descriptions) is never concatenated into system prompts; tool results are data-typed, not free text where avoidable.
- Evaluation: golden-set of 200 query→expected-map-state pairs run in CI against the query pipeline; correlation engine has unit tests against synthetic data with known ρ.
